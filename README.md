# Almaty Build Map

One web page: a **Yandex map of Almaty** with a pin for every current construction project and its
**deadline**. Categories: apartments (ЖК), roads, repairs / other state construction. Click a pin →
name, who builds it, deadline, stage, link to the source. No accounts, no backend, no search.

Full spec and source research: [HANDOVER.md](HANDOVER.md). This README is the "how to run it" part.

```
scraper (Python, weekly)  ──►  data/projects.geojson  ──►  index.html (Yandex Maps JS API 3.0)
        │                                                        ▲
        └── GitHub Actions cron commits the file ────────────────┘   served by GitHub Pages
```

## Quick start

```bash
pip install -r requirements.txt
python -m pytest -q                         # 41 tests, fixtures only, no network
python -m scraper.build --limit 5           # smoke test → data/projects.sample.geojson (~10 s)
python -m scraper.build                     # full crawl → data/projects.geojson (~730 pages, 20–25 min)
python -m http.server 8000                  # then open http://localhost:8000/
```

Open the page from an http server, not as `file://` (the page fetches the GeoJSON).

## Configuration

| Where | What | Needed for |
|---|---|---|
| `index.html`, constant `YANDEX_MAPS_API_KEY` | Yandex Maps JS API key | the map itself; without it the page shows a plain list |
| env `YANDEX_GEOCODER_KEY` / GitHub secret | same key (service "JavaScript API и HTTP Геокодер") | `roads.py`; cached results in `data/geocode_cache.json` keep working without it |
| env `CONTACT_EMAIL` / GitHub variable | contact address put into the bot's User-Agent | polite crawling (HANDOVER §7); the crawl warns if unset |
| env `GOSZAKUP_TOKEN` / GitHub secret | goszakup OWS v3 bearer token | enables the repairs feed (still a stub) |
| env `PROJECT_URL` | repo URL for the User-Agent | optional |

Get the keys in the developer cabinet: <https://developer.tech.yandex.ru/> → "Подключить API".
The cabinet issues **separate keys per service**: one for *JavaScript API* (goes into `index.html`) and
one for *API Геокодера* (goes into `YANDEX_GEOCODER_KEY`). Both are free-tier.

**JavaScript API 3.0 keys are rejected ("Invalid api key", HTTP 403) until a restriction is configured.**
In the key settings add HTTP Referer entries: `localhost` and `127.0.0.1` for local testing, plus your
GitHub Pages host (e.g. `bekzat.github.io`) when you publish. The key status changes from "Не настроен"
to active a few minutes after saving.

## Data

`data/projects.geojson` is a FeatureCollection; every feature carries the same properties
(schema in HANDOVER §4): `id`, `category`, `name`, `builder`, `address`, `status`, `deadline`,
`started_at`, `stage_note`, `source_url`, `updated_at`. Coordinates are `[lon, lat]`.
Top-level extras: `generated_at` (shown as "Обновлено" on the page), `counts`, `feeds` (per-feed
status – the page shows a warning if a feed failed and old data is being displayed), `today`.

### Apartments (Krisha)

* List: `https://krisha.kz/complex/search/almaty/?state[]=1&state[]=2&page=N`, 12 cards per page,
  each `div.complex-card[data-complex-alias]`.
* Detail: coordinates from the embedded `window.data.complex.map` JSON (no geocoding); builder,
  status and "Срок сдачи" from the `.complex__sidebar-info` blocks; КЖК guarantee from
  `.complex-docs__list-item`; parameters from `dl.complex-parameters__block`.
* Deadline rule: latest очередь date among not-yet-delivered очереди (date ≥ today). All delivered →
  `status: done` (kept in the file, hidden by default). Every date in the past but still "Строящийся"
  → overdue → red on the map. `started_at` is inferred from the earliest "Ход строительства" entry.
* If Krisha starts blocking: stop, don't fight it; alternatives are listed in HANDOVER §3.1.

### Roads (CSV)

`data/roads.csv` columns: `name,street,from_street,to_street,work_type,deadline,source_url,notes`
(optional extra columns: `status`, `contractor`). Leave `name` empty to get "Street (from – to)".
`deadline` accepts `2026-10-31`, `Q4 2026`, `IV квартал 2026` and similar. Both ends are geocoded
as intersections (`Алматы, {street}, {cross}`, then `Алматы, пересечение {a} и {b}`) and cached in
`data/geocode_cache.json`. Rows that fail to geocode are skipped with a warning – check the first
real run and adjust `QUERY_TEMPLATES` in `scraper/roads.py` if Yandex wants a different phrasing.

### Repairs (goszakup) – stub

Written against the v3 docs, never executed. Once the token arrives:
`GOSZAKUP_TOKEN=… python -m scraper.build --only goszakup -v`, fill `CUSTOMER_BINS`, fix the
`TODO(token)` field names.

## Deploy (GitHub Pages)

1. Push the repo to GitHub, default branch `main`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions: secret `YANDEX_GEOCODER_KEY`, variable `CONTACT_EMAIL`
   (secret `GOSZAKUP_TOKEN` later).
4. Actions → "Refresh data and deploy" → Run workflow. The cron then runs every Monday 03:00 UTC.

The refresh job runs the tests, crawls, commits `data/` if anything changed, and the deploy job
publishes `index.html` + `data/`. A failed feed keeps its previous features and turns the run red.

## Scraping rules (HANDOVER §7, enforced in `PoliteSession`)

≥ 1.5 s between requests, single thread, honest User-Agent, robots.txt respected, backoff on
429/5xx, stop after 5 consecutive failures, raw HTML cached locally. No phone numbers, ИИН or any
personal data are collected – only ЖК/lot-level facts plus a link back to the source.
